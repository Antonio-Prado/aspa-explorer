What you are looking at

An ASPA (Autonomous System Provider Authorization) is a signed object published in the RPKI. In it, a customer AS lists the ASes that are allowed to act as its upstream providers. Routers that validate AS paths use these lists to spot route leaks and some forged paths.

ASPA Explorer shows every ASPA that a Routinator validator currently considers valid. Nothing here is edited or interpreted: the page reads the validator's output and presents it so you can search it and see the big picture.

At the top of the page a line summarises the data: the number of ASPAs, the time of the last validation run (always in UTC) and the version of the validator that produced it.

Looking up an AS

Type an AS number in the box at the top and press Look up. All of these are accepted: AS680, as 680 and 680. AS numbers go up to 4294967295. Anything else shows a short hint instead of a result.

The result has a header with the AS number and two outside links, bgp.tools and RIPEstat, that open in a new tab. Below it are two columns:

Its own ASPA
The providers that this AS authorizes, shown as clickable chips. For each ASPA object the page also lists the RIR (the trust anchor it comes from), its validity period (not before to not after) and the repository address of the signed object. If the AS has not published an ASPA the page says so: its upstream relationships cannot be verified.
Named as a provider
Every ASPA, from any customer, that lists this AS as a provider, with the number of such ASPAs. The list is empty for ASes that nobody names as a provider.

Long lists are cut after a few dozen chips; use +N more to expand them. Click any chip to jump to that AS.

An AS0 · no providers chip is not a link. It is the way an AS declares that it has no upstream providers at all, as networks at the top of the hierarchy do.

The overview

The four tiles

ASPAs
Customer ASes that have a valid ASPA.
Provider ASes
Distinct ASes that appear as a provider in at least one ASPA. AS0 is not counted.
Median providers
The middle value of the number of providers per ASPA, with the size of the largest provider set underneath.
No-provider ASPAs
ASPAs whose only provider is AS0.

The three charts

ASPAs by RIR
How many ASPAs each trust anchor (AFRINIC, APNIC, ARIN, LACNIC, RIPE NCC) validates. Each ASPA is counted once, under the trust anchor of its first source object. The percentage in the tooltip is relative to all ASPAs.
Providers per ASPA
A column chart of how many providers each customer declares, from 1 to 9 and then 10+. An ASPA with AS0 counts as one provider.
Most-named providers
The ten ASes that appear in the most ASPAs as a provider. Select a bar to look that AS up.

Hover over a bar or column, or move the keyboard focus onto it, to see the exact value in a tooltip.

The table of all ASPAs

The table lists every ASPA in order of customer AS number, with the customer, its providers and the RIR.

  • Filter by AS number shows the ASPAs where that AS is the customer or one of the providers. It needs a complete AS number; partial numbers or text are not searched, and the counter tells you so.
  • All RIRs restricts the table to one trust anchor. It combines with the AS filter.
  • The counter shows how many ASPAs match.
  • The table shows 100 rows at a time. Use Show N more under it to load the next batch. Provider sets longer than eight entries can be expanded with +N more.
  • Every AS in the table is a link to its lookup.

Links and keyboard use

Each lookup has its own address: https://aspa.ping6.it/#AS680 opens the page already showing AS680, so you can bookmark or share a result. The same works for any AS number.

Everything can be used from the keyboard: the lookup field, filters, chips, chart bars and the buttons are all reachable with Tab, and the tooltips follow the focus. The page follows your system's light or dark setting and adapts to narrow screens.

Where the data comes from

The data comes from Routinator, the RPKI validator run at rpki.ping6.it. It validates the RPKI repositories of all five RIRs and the page reads two of its outputs:

  • the list of valid ASPAs (jsonext, route origins and router keys left out), and
  • the validator status, which supplies the last validation time and the Routinator version.

The validator refreshes about every 10 minutes and the web server keeps its answer for 2 minutes, so a new ASPA can take a little while to show up here. The last validation time in the header tells you how fresh the data is.

Reading the results

  • No ASPA is not an error. Many ASes have not published one yet. It only means the page has nothing to show for them.
  • The page shows what this validator sees. Another validator, or the same one a few minutes later, may differ slightly.
  • An ASPA lists providers for one customer. It says nothing about peers, and it does not check any specific BGP route: that is done by routers that use these objects.
  • Validity dates are those in the signed object. An expired ASPA is not shown, because the validator discards it.

If something does not load

If the page shows Could not load the ASPA data, the validator is probably restarting. Wait a minute and reload. If it persists, the error text in the message shows which request failed.

Accessibility

ASPA Explorer is built to be usable by everyone, including people who use a keyboard, a screen reader, magnification or high-contrast settings. The target is conformance with the Web Content Accessibility Guidelines (WCAG) 2.1 at level AA. The pages have been checked with the axe-core automated testing tool in both the light and the dark theme, with no issues reported. They have not been audited by an independent body or tested with screen-reader users, so there may be gaps that an automated tool cannot find.

What is in place

  • Keyboard. Every control can be reached and used with Tab, Shift+Tab, Enter and Space. The focused element has a visible outline. A Skip to main content link appears first when you press Tab.
  • Structure. Pages use landmarks (header, main, footer) and a single heading hierarchy. The table has a caption and column headers, and every form field has a label.
  • Charts. Each bar or column can take keyboard focus, carries its label and value as text, and shows its tooltip on focus as well as on hover. The exact numbers are also in the table and in the lookup results, so no information depends on seeing the chart.
  • Colour. Text meets the WCAG AA contrast ratio in the light and the dark theme, which follow your system setting. Colour is never the only way something is shown.
  • Screen readers. Lookup results are announced when they appear. Links in the footer open in a new tab and say so in their accessible name. Decorative images are hidden from assistive technology and meaningful ones have a text alternative.
  • Zoom and small screens. The layout reflows without horizontal scrolling down to a width of 320 pixels, which is what a desktop window shows at 400% zoom.
  • Motion. If your system asks for reduced motion, the page does not animate scrolling.

Known limitations

  • The tables and chips can be long: a large provider set or the 100-row table pages are tiring to read with a screen reader. Use the lookup or the AS filter to narrow them down.
  • The outside links (bgp.tools, RIPEstat) and the validator's raw JSON are not under this project's control.

Feedback

If you meet a barrier, please tell us: open an issue in the project repository, or write to antonio@prado.it saying which page, what you were trying to do, and which browser and assistive technology you use. Reports are read and answered.

About this page

ASPA Explorer is a small static page with no external dependencies and no cookies: your lookups happen in your browser and are not sent anywhere. The only thing this site learns about you is what any web server learns from a request; the footer shows the address your request came from, as the server sees it, and links it to RIPEstat; nothing is sent to RIPEstat unless you follow the link. The footer links to the project on the DEI GitLab and shows the release you are using and the commit it was built from.

The source code, the changelog and instructions to report a problem are in the project repository.
