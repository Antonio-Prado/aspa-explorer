One AS

GET https://aspa.ping6.it/api/v1/as/{number} returns a JSON document for the AS with that number (3333, not AS3333). Any valid 32-bit AS number answers; an AS that has never had an ASPA and is named by none gets "published": false and empty lists. An invalid number is a 404. Cross-origin requests are allowed.

curl https://aspa.ping6.it/api/v1/as/8283
Fields of the answer
FieldMeaning
asn, numberThe AS, as AS8283 and as 8283.
generatedWhen the file was built (UTC), at most a few minutes ago.
aspa.publishedWhether a valid ASPA of this AS exists now.
aspa.providersThe providers it authorizes, by number; ["AS0"] means it declares no provider.
aspa.no_providerstrue for an ASPA made of AS0 alone.
aspa.sourcesThe signed objects: trust anchor, validity, rsync address.
provider_ofThe ASes whose ASPA names this AS as a provider.
seen_in_bgpWhether the RIPE RIS collectors see the AS in routes (null when unknown).
qualityFindings about its ASPA, with a kind, a severity (error, warning, note) and a detail. The kinds are explained in the guide.
historyEvery change of its own ASPA since 12 October 2023: date, kind (new, changed, removed), the providers after the change and the ones added and dropped.
named_as_provider_historyThe changes of other ASPAs that added or dropped this AS as a provider.
linksThe page, the badge and the feed of the AS.

The schema is also available as OpenAPI 3.1.

Badge

GET https://aspa.ping6.it/badge/AS8283.svg is a small image that says how many providers the AS has authorized (ASPA: 5 providers), or none, no providers (AS0), or published, with errors when the quality checks find an error. Link it to the page of the AS:

[![ASPA of AS8283](https://aspa.ping6.it/badge/AS8283.svg)](https://aspa.ping6.it/as/AS8283)

The same snippet, in Markdown and HTML, is under Add the badge to your site when you look up an AS. Browsers and proxies may keep a badge for ten minutes.

Atom feed

GET https://aspa.ping6.it/feed/AS8283.atom lists the latest 100 changes that concern the AS: its own ASPA (new, changed, removed) and the ASPAs of others that add or drop it as a provider. Add it to a feed reader to be told when something changes. A feed for an AS with no history is valid and empty; it fills when something happens. The feed of all changes is /changes.atom.

Subscriptions and webhooks

POST https://aspa.ping6.it/api/v1/subscriptions with a JSON body {"kind": "webhook", "target": "https://example.org/hook", "asn": "AS3333"} (or "kind": "email" with an address, which then has to be confirmed through a link sent to it). The same events as in the feed. A few requests an hour are allowed per visitor.

For a webhook, the service first calls the address with {"type": "verification", "challenge": "…", "asn": "AS3333", "unsubscribe": "…"}; reply with a 2xx status and a body that contains the challenge. The answer to the subscription then has the secret, once. A delivery looks like this:

POST /hook
X-ASPA-Timestamp: 1792224830
X-ASPA-Signature: sha256=…      HMAC-SHA256(secret, timestamp + "." + body), hex

{"type": "aspa.change", "asn": "AS3333", "relation": "own",
 "text": "The ASPA of AS3333 added AS1299. It now lists 3 providers: AS174, AS1299, AS3356.",
 "time": "2026-10-17T10:00:00.000Z",
 "change": {"customer": "AS3333", "kind": "changed", "providers": ["AS174", "AS1299", "AS3356"], "added": ["AS1299"], "dropped": []},
 "page": "https://aspa.ping6.it/as/AS3333",
 "unsubscribe": "https://aspa.ping6.it/api/v1/subscriptions/unsubscribe?token=…"}

Add "leaks": true to the body to receive, once a day, the new places of valley that involve the AS as well (only true counts; it cannot be changed later, subscribe again). Such a delivery has "type": "aspa.leak", the same signature and a place object: {"role": "valley" | "gap", "kind": "leak" | "gap", "from": "AS…", "to": "AS…", "between": ["AS…"], "feeders": 5, "routes": 10}. The data comes from /api/v1/leaks-by-as.json (the places seen by at least three feeders, for each AS), the totals of each day from /api/v1/leaks-history.json and the file of an earlier day (the last 60) from /api/v1/leaks-by-as/YYYYMMDD.json.

relation is own for a change of the ASPA of the AS and provider when another ASPA adds or drops it; kind is new, changed or removed. Check the signature and reject a timestamp more than a few minutes old. Deliveries are not retried; five failures in a row switch the webhook off. To stop, send a POST to the unsubscribe address.

Webhook addresses must be https with a public host name; the service refuses names that resolve to private or local addresses, does not follow redirects and waits five seconds at most.

Download the whole list

Every valid ASPA, one per row: the customer, its providers (separated by spaces in the CSV), the RIR whose trust anchor holds it and the validity of the signed object. The files are rebuilt every 15 minutes. Direct addresses, for scripts: /api/v1/aspas.csv and /api/v1/aspas.json.

Loading the list

Everything at once

  • /data/aspas.json: all valid ASPAs, as Routinator's jsonext (route origins and router keys left out), with every detail of the signed objects.
  • /api/v1/meta.json: when the per-AS files were built and how many there are.
  • /api/v1/adoption.json: the adoption numbers: networks seen in BGP and how many have an ASPA, by RIR, country and size, and the 100 largest networks. Built once a day; the sources are named in the file.
  • The daily history, the events and the BGP visibility are plain files on the history branch of the public project (opens in a new tab).

Freshness and fair use

The ASPAs come from the validator at rpki.ping6.it (opens in a new tab), which refreshes about every 10 minutes; the per-AS files are rebuilt every 15 minutes and may be cached for a few minutes more, so allow up to half an hour for a change to show. Please do not poll one AS more than once every 15 minutes, and prefer /data/aspas.json when you need many ASes. The service is a research testbed with no guarantee of availability.
